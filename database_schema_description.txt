================================================================================
           COMPLETE DATABASE SCHEMA & RELATIONSHIP DOCUMENTATION
================================================================================

เอกสารนี้อธิบายโครงสร้างฐานข้อมูล PostgreSQL ทั้งหมดที่ระบบใช้ (อัปเดตล่าสุด
จาก schema จริงในฐานข้อมูล) ครอบคลุม:
  - ตารางทั้งหมด 25 ตาราง พร้อมคอลัมน์จริงและความสัมพันธ์ (FK)
  - สถานะการใช้งานของแต่ละตาราง (โค้ดใช้จริง / ยังไม่ใช้ / legacy)
  - คำแนะนำสำหรับตารางที่เกินมา

--------------------------------------------------------------------------------
0. สรุปภาพรวม (TABLES OVERVIEW)
--------------------------------------------------------------------------------

ตารางทั้งหมด 25 ตาราง แบ่งตามสถานะการใช้งานโดยโค้ด (app.py + backend/)
เป็น 3 กลุ่ม:

  A) ตารางที่โค้ดใช้งานจริง (ACTIVE) .......... 19 ตาราง
  B) ตารางที่ยังไม่มีโค้ดใช้งาน (UNUSED) ....... 5 ตาราง

  ตาราง legacy ที่แนะนำให้ลบ/ย้ายข้อมูล ....... 1 ตาราง (user_skill_progress)

หมายเหตุ: db_store.ensure_schema() สร้างตารางหลัก และ
study_buddy_store.ensure_social_schema() สร้างตารางโซเชียลแบบ idempotent

3. หมวดผู้ใช้งานและโปรไฟล์ (USER & PROFILE MODULE) — ACTIVE
--------------------------------------------------------------------------------

[TABLE: users]
คำอธิบาย: เก็บข้อมูลบัญชีผู้ใช้งานสำหรับเข้าสู่ระบบ (Authentication) และ UID
สำหรับค้นหาเพื่อน/สแกน QR
คอลัมน์ (ตามลำดับจริงในฐานข้อมูล):
- id (BIGSERIAL, PK)           : รหัสประจำตัวผู้ใช้งาน
- email (VARCHAR, UNIQUE)      : อีเมลผู้ใช้งาน (ห้ามซ้ำ)
- password_hash (VARCHAR)      : รหัสผ่านที่ผ่านการเข้ารหัสแล้ว (Hash)
- created_at (TIMESTAMP)       : วันเวลาที่ลงทะเบียน
- uid (VARCHAR, UNIQUE)        : รหัส UID สั้น ๆ สำหรับค้นหาเพื่อน
เงื่อนไขพิเศษ: UNIQUE (uid, email)

[TABLE: user_profiles]
คำอธิบาย: เก็บข้อมูลโปรไฟล์ Gamification, สายอาชีพ และรูปโปรไฟล์หลักที่ใช้ร่วมกัน
คอลัมน์:
- user_id (BIGINT, PK, FK)       : รหัสผู้ใช้ (-> users.id / CASCADE)
- display_name (VARCHAR)         : ชื่อที่ใช้แสดงผลในระบบ
- level (INTEGER)                : เลเวลปัจจุบัน (ค่าเริ่มต้น: 1)
- current_exp (INTEGER)          : EXP สะสมปัจจุบัน (ค่าเริ่มต้น: 0)
- current_career_id (BIGINT, FK) : สายอาชีพที่เลือกเรียน (-> careers.id / SET NULL)
- profile_picture (BYTEA)        : รูปโปรไฟล์หลัก เก็บเป็น binary และ render เป็น data URL
- updated_at (TIMESTAMP)         : เวลาอัปเดตล่าสุด

[TABLE: user_node_progress]
คำอธิบาย: บันทึกความก้าวหน้าการเรียนของผู้ใช้แต่ละคนในแต่ละวิชา (กราฟปัจจุบัน)
คอลัมน์:
- id (BIGSERIAL, PK)            : รหัสบันทึกรายการ
- user_id (BIGINT, FK)          : รหัสผู้เรียน (-> users.id / CASCADE)
- node_id (BIGINT, FK)          : รหัสวิชา (-> nodes.id / CASCADE)
- status (VARCHAR)              : 'locked' | 'unlocked' | 'completed'
- completed_at (TIMESTAMP)      : วันเวลาที่เรียนจบวิชานั้น ๆ
เงื่อนไขพิเศษ: UNIQUE (user_id, node_id) ป้องกันการบันทึกซ้ำ

4. หมวดแผนผังทักษะและสายอาชีพ (SKILL TREE & CAREER MODULE) — ACTIVE
--------------------------------------------------------------------------------

[TABLE: careers]
คำอธิบาย: เก็บข้อมูลสายอาชีพทั้งหมด (ปัจจุบัน 6 สาย)
คอลัมน์:
- id (BIGSERIAL, PK)   : รหัสสายอาชีพ
- title (VARCHAR)      : ชื่อสายอาชีพ (เช่น Software Engineer / Fullstack)
- description (TEXT)   : คำอธิบายรายละเอียดของสายอาชีพ

[TABLE: subjects]
คำอธิบาย: (ตารางใหม่) หมวดหมู่/กลุ่มวิชา ใช้สำหรับแบ่งสีและจัดกลุ่มบน Skill Tree
คอลัมน์:
- id (BIGSERIAL, PK)   : รหัสหมวดวิชา
- name (VARCHAR)       : ชื่อหมวดวิชา (เช่น Core Skills)
- thai_name (VARCHAR)  : ชื่อภาษาไทย
- color (VARCHAR)      : สีที่ใช้แสดงผลบนแผนผัง
หมายเหตุ: ปัจจุบันมีหมวดเดียวคือ "Core Skills" และ node ทุกตัวถูก backfill ให้อยู่หมวดนี้

[TABLE: nodes]
คำอธิบาย: คลังวิชา/โหนดทักษะส่วนกลาง (Master Data) — 40 วิชา
คอลัมน์ (คอลัมน์หลัง exp_reward เป็นคอลัมน์ที่เพิ่มใหม่จาก prototype เดิม):
- id (BIGSERIAL, PK)          : รหัสวิชา/โหนด
- title (VARCHAR)             : ชื่อวิชา (เช่น Git & Version Control Workflow)
- description (TEXT)          : รายละเอียดเนื้อหาของวิชา
- exp_reward (INTEGER)        : EXP ที่ได้รับเมื่อเรียนจบ (ค่าเริ่มต้น: 100)
- subject_id (BIGINT)         : [ใหม่] หมวดวิชา (-> subjects.id)
- thai_title (VARCHAR)        : [ใหม่] ชื่อวิชาภาษาไทย (ถ้าว่างจะใช้ title)
- career_relevance (INTEGER)  : [ใหม่] ความเกี่ยวข้องกับอาชีพ (ค่าเริ่มต้น: 3)
- techniques (TEXT JSON)      : [ใหม่] เทคนิคสำคัญสำหรับเรียนวิชานี้ (array ของ string)
- learning_outcomes (TEXT JSON): [ใหม่] สิ่งที่ทำได้เมื่อเรียนจบ (array ของ string)
- real_world (TEXT JSON)      : [ใหม่] ตัวอย่างการนำไปใช้จริง (array ของ string)
หมายเหตุ: เทคนิค/ผลลัพธ์/การนำไปใช้จริง ถูก backfill แล้วใน data/seed_node_details.py

[TABLE: career_nodes]
คำอธิบาย: ตารางเชื่อม Many-to-Many ระหว่าง สายอาชีพ (careers) และ วิชา (nodes)
คอลัมน์:
- career_id (BIGINT, PK, FK)  : รหัสสายอาชีพ (-> careers.id / CASCADE)
- node_id (BIGINT, PK, FK)    : รหัสวิชา (-> nodes.id / CASCADE)
- step_order (INTEGER)        : ลำดับการแสดงผลบน Skill Tree (ค่าเริ่มต้น: 1)
- is_mandatory (BOOLEAN)      : วิชาบังคับหรือวิชาเลือก (ค่าเริ่มต้น: TRUE)

[TABLE: node_prerequisites]
คำอธิบาย: เก็บเงื่อนไขวิชาบังคับก่อนหน้า (Prerequisite) ของแต่ละโหนด — เป็น Edge
ของ Graph Engine (Graph Engine เป็น source of truth ของเส้นทางการเรียน)
คอลัมน์:
- node_id (BIGINT, PK, FK)              : รหัสวิชาหลัก (-> nodes.id / CASCADE)
- prerequisite_node_id (BIGINT, PK, FK) : วิชาที่ต้องเรียนผ่านก่อน (-> nodes.id / CASCADE)

5. หมวดตราความสำเร็จและระดับ (ACHIEVEMENTS & RANKS MODULE) — ACTIVE
--------------------------------------------------------------------------------

[TABLE: achievements]
คำอธิบาย: (ตารางใหม่) รายการตราความสำเร็จ (Badge) ทั้งหมด — seed อัตโนมัติ 4 รายการ
คอลัมน์:
- id (BIGSERIAL, PK)         : รหัสตรา
- title (VARCHAR)            : ชื่อตรา (First Step, Code Novice, ...)
- description (TEXT)         : คำอธิบาย/เงื่อนไข
- icon_url (VARCHAR)         : ลิงก์รูปไอคอน
- condition (TEXT)           : [ใหม่] เงื่อนไขปลดล็อกในรูป JSON
- category (VARCHAR(40))     : แยก badge ทั่วไปออกจาก career_progress tier
                              เช่น {"type": "exp", "target": 500}
                              type ที่รองรับ: completed_skills | exp | friends | study_sessions

[TABLE: user_achievements]
คำอธิบาย: (ตารางใหม่) บันทึกตราที่ผู้ใช้แต่ละคนปลดล็อกแล้ว
คอลัมน์:
- user_id (BIGINT, PK, FK)        : รหัสผู้ใช้ (-> users.id / CASCADE)
- achievement_id (BIGINT, PK, FK) : รหัสตรา (-> achievements.id / CASCADE)
- unlocked_at (TIMESTAMP)         : วันเวลาที่ปลดล็อก

[TABLE: ranks]
คำอธิบาย: (ตารางใหม่) ระดับ Rank ของผู้เรียน — seed อัตโนมัติ 5 ระดับ
                      (01 Starter 0% / 02 Core Learner 25% / 03 System Builder 50%
                       04 Career Ready 75% / 05 Career Master 100%)
คอลัมน์:
- id (BIGSERIAL, PK)      : รหัส Rank
- code (VARCHAR)          : รหัสย่อ (01, 02, 03, 04)
- name (VARCHAR)          : ชื่อ Rank (Starter, Core Learner, ...)
- hint (VARCHAR)          : คำแนะนำสั้น ๆ
- min_progress (INTEGER)  : เปอร์เซ็นต์ความคืบหน้าขั้นต่ำของ Rank นี้

6. หมวดโซเชียลและ STUDY BUDDY — ACTIVE
--------------------------------------------------------------------------------

[TABLE: friendships]
คำอธิบาย: ความสัมพันธ์เพื่อนและคำขอเป็นเพื่อน ใช้จริงใน Friend Hub และอ่าน
จำนวน status='accepted' เพื่อคำนวณ Achievement
คอลัมน์:
- id (BIGSERIAL, PK)       : รหัสรายการความสัมพันธ์
- user_id (BIGINT, FK)     : ผู้ขอแอดเพื่อน (-> users.id)
- friend_id (BIGINT, FK)   : เพื่อนที่ถูกแอด (-> users.id)
- status (VARCHAR)         : 'pending' | 'accepted' | 'blocked'
- created_at (TIMESTAMP)   : วันเวลาที่แอด
เงื่อนไขพิเศษ: UNIQUE (user_id, friend_id)

[TABLE: study_sessions]
คำอธิบาย: ห้องติว (Study Session Rooms) — ปัจจุบันโค้ดอ่านเฉพาะจำนวนห้องที่ผู้ใช้
เป็น Host เพื่อปลดล็อกตรา "Study Buddy Host"
คอลัมน์:
- id (BIGSERIAL, PK)         : รหัสห้องติว
- host_user_id (BIGINT, FK)  : ผู้เป็นเจ้าของห้อง (-> users.id)
- node_id (BIGINT, FK)       : วิชาที่กำลังติว (-> nodes.id / SET NULL)
- title (VARCHAR)            : ชื่อห้องติว
- is_active (BOOLEAN)        : TRUE = เปิดอยู่, FALSE = ปิดแล้ว
- created_at (TIMESTAMP)     : วันเวลาที่สร้างห้อง

[TABLE: study_groups]
คำอธิบาย: กลุ่มติวของผู้ใช้และเพื่อน
คอลัมน์: id, name, owner_user_id (-> users.id), graph_career_id,
        graph_focus_skill_id, created_at

[TABLE: study_group_members]
คำอธิบาย: สมาชิกและบทบาทในกลุ่มติว
คอลัมน์: group_id (PK, -> study_groups.id), user_id (PK, -> users.id),
        role, joined_at

[TABLE: study_group_messages]
คำอธิบาย: ข้อความ text ภายในกลุ่มติว พร้อมตัวตนผู้ส่งจาก user_profiles
คอลัมน์: id, group_id (-> study_groups.id), sender_user_id (-> users.id),
        content, created_at

[TABLE: buddy_notifications]
คำอธิบาย: การแจ้งเตือนคำขอเพื่อน กิจกรรม การแชร์เส้นทาง และกลุ่มติว
คอลัมน์: id, user_id, actor_user_id, kind, title, body, payload (JSONB),
        read_at, created_at

[TABLE: study_path_shares]
คำอธิบาย: snapshot ของ Skill Tree ที่แชร์ให้เพื่อน โดยข้อมูลเส้นทางมาจาก Graph Engine
คอลัมน์: id, sender_user_id, receiver_user_id, graph_career_id, message,
        snapshot (JSONB), created_at

[TABLE: world_chat_messages]
คำอธิบาย: ข้อความ Global Chat แบบ text ที่ผู้ใช้ที่เข้าสู่ระบบทุกคนอ่านและเขียนได้
คอลัมน์:
- id (BIGSERIAL, PK)       : รหัสข้อความ
- user_id (BIGINT, FK)     : ผู้ส่ง (-> users.id / CASCADE)
- content (TEXT)           : เนื้อหาข้อความ สูงสุด 1000 ตัวอักษรใน API
- created_at (TIMESTAMP)   : เวลาที่ส่ง
หมายเหตุ: API join users และ user_profiles เพื่อส่ง display name, UID และ
profile_picture ของเจ้าของข้อความให้ UI render

7. ตารางที่ยังไม่มีโค้ดใช้งาน (UNUSED) — legacy social design
--------------------------------------------------------------------------------

ตารางกลุ่มนี้มาจาก social design รุ่นเดิมและยังไม่มีโค้ดอ่านหรือเขียน

[TABLE: certificates] (1 แถว)
คำอธิบาย: เก็บข้อมูลไฟล์เกียรติบัตรดิจิทัล (E-Certificate) ที่ผู้ใช้อัปโหลด
คอลัมน์: id, user_id (-> users.id), title, issued_by, file_url, uploaded_at

[TABLE: session_members] (2 แถว)
คำอธิบาย: สมาชิกที่เข้าร่วมห้องติว
คอลัมน์: session_id (PK, -> study_sessions.id), user_id (PK, -> users.id), joined_at

[TABLE: chat_messages] (3 แถว)
คำอธิบาย: แช็ตในห้องติว ทั้งข้อความ รูป GIF และการ์ดนัดหมาย
คอลัมน์: id, session_id (-> study_sessions.id), sender_id (-> users.id),
        message_type ('text'|'gif'|'appointment'), content, created_at

[TABLE: friend_requests] (0 แถว)
คำอธิบาย: คำขอเป็นเพื่อน (แยกออกจาก friendships)
คอลัมน์: id, requester_user_id (-> users.id), addressee_user_id (-> users.id),
        status ('pending'), message, created_at, responded_at
เงื่อนไขพิเศษ: UNIQUE (requester_user_id, addressee_user_id)

[TABLE: study_buddy_friendships] (0 แถว)
คำอธิบาย: ความสัมพันธ์คู่หูติว (แนวคิดคล้าย friendships แต่แยกเจตนา)
คอลัมน์: user_id (PK, -> users.id), friend_user_id (PK, -> users.id), created_at

8. ตาราง LEGACY ที่ไม่ได้ใช้งาน (แนะนำให้จัดการ)

[TABLE: user_skill_progress] (24 แถว)

9. คำแนะนำ (RECOMMENDATIONS)
--------------------------------------------------------------------------------

1) user_skill_progress (LEGACY)
   - แนะนำ: ตรวจสอบว่ายังมีผู้ใช้ที่ยังไม่ได้ย้ายข้อมูลหรือไม่ ถ้าไม่มี ให้ DROP
     ตารางทิ้ง เพื่อไม่ให้สับสนกับ user_node_progress (ชื่อคล้ายกันมาก)
   - ถ้าอยากเก็บประวัติ: ย้ายข้อมูลโดย map skill_id (string) -> nodes.id (BIGINT)
     โดยเทียบชื่อวิชาเก่ากับ nodes.title ให้ตรงกันก่อน แล้วจึงลบตาราง

2) ตาราง social design รุ่นเดิมที่ยังไม่ใช้ (certificates, chat_messages,
   session_members, friend_requests, study_buddy_friendships)
   - พิจารณาย้ายข้อมูลหรือลบเมื่อยืนยันว่าไม่มี feature เก่าอ้างอิง
   - อย่าสับสน chat_messages รุ่นเดิมกับ study_group_messages และ
     world_chat_messages ที่ระบบปัจจุบันใช้งานจริง

3) การเพิ่มตารางใหม่ในอนาคต
   - ให้เพิ่ม DDL ใน SCHEMA_STATEMENTS (backend/db_store.py) เสมอ เพื่อให้
     ฐานข้อมูลใหม่ (fresh DB) มี schema ครบเท่ากับฐานข้อมูลจริง
   - หลีกเลี่ยงการสร้างตารางด้วยสคริปต์ครั้งเดียวที่ไม่ได้ commit ไว้ใน repo

4) ข้อมูลเนื้อหาวิชา (techniques / learning_outcomes / real_world)
   - backfill เสร็จแล้วสำหรับ 40 nodes ผ่าน data/seed_node_details.py
   - สคริปต์นี้ idempotent (อัปเดตเฉพาะ node ที่ยังว่าง) ใช้รันซ้ำได้กับฐานข้อมูลใหม่
